# 서동민 · 게임 기획 포트폴리오

공개 홈페이지: https://standupdongmin.github.io/dongmin-portfolio/

빌드나 프레임워크 설치 없이 실행하는 HTML·CSS·JavaScript 사이트입니다.

## 파일 구성

- `index.html` / `서동민.html`: 같은 화면으로 진입합니다. 페이지 순서, 메뉴, 첫 화면의 짧은 문구와 프로젝트 개요를 관리합니다.
- `content.js`: 작업 11개의 제목·요약·상세, 프로필·역량 13개, 게임 기록 9개입니다.
- `assets.js`: 실제 이미지, 확대 원본, 문서와 연락처 경로입니다.
- `styles.css`: 색상, 타이포그래피, 여백과 반응형 배치입니다.
- `portfolio.js`: 콘텐츠 렌더링, 제작 과정, 이미지 확대, 문서 링크와 모바일 메뉴입니다.
- `assets/media/`: 실제 프로젝트 작업 이미지와 최신 PDF에서 렌더링한 문서 표지·페이지입니다.
- `assets/documents/`: 홈페이지에서 열람·다운로드하는 문서입니다.

## 화면 구성

첫 화면 → 소개·경험 → 포트폴리오 개요 PDF → The Battle Arena 대표 프로젝트 → Project Jump → 개인 기획서 → 구현 역량·AI 활용 → 연락처 순서입니다. 원본 개요의 팀 프로젝트 참여 기록을 기준으로 두 교내 프로젝트를 팀 작업으로 구분합니다. 개인 문서는 AI의 시스템 기획서와 가디언의 콘텐츠 기획서로 구분합니다.

본문 최대 폭은 1,240px입니다. 배경 `#101110`, 패널 `#191B19`, 구분선 `#343733`, 본문 `#EFEEE7`, 보조 글자 `#A2A59C`, 포인트 `#FF783C`를 사용합니다. 72px 헤더는 모바일에서 64px로 바뀌며 모바일 좌우 여백은 20px입니다.

게임 화면은 16:9 프레임에서 원본 비율을 유지합니다. 이미지를 누르면 확대 창이 열리며, 원본 이미지 링크도 제공합니다. 긴 제작 과정은 3개 요약 뒤에 넓은 본문과 실제 작업 자료로 이어집니다. 닫기 버튼과 Esc를 지원합니다. 플레이 경험 9개는 소개 아래에서 펼쳐볼 수 있습니다.

## 내용과 자료 수정

작업 설명은 `content.js`의 `works`에서 수정합니다. `details`는 세 파트의 문단 배열입니다. `detailLabels`로 작업별 제목을 지정합니다. 제작 작업은 **작업 목표 → 작업 내용 → 확인 기준**, 개인 기획서는 **기획 의도 → AI 설계 내용 또는 전투 설계 → 검토 기준**으로 구분합니다. 원문에 없는 개인 회고를 제작 경험으로 쓰지 않습니다. HTML 태그 대신 일반 텍스트를 입력하고 따옴표·쉼표·대괄호를 유지합니다.

긴 본문은 문장별로 줄을 나누고, 원래 문단 사이에는 더 넓은 여백을 둡니다. 해결 과정의 `solutionGroups`는 `details[1]`의 문장을 0부터 세는 번호로 참조해 소제목과 목록으로 묶습니다. 실제 문구는 `details` 한 곳에서 수정하며, 문장 수나 순서를 바꾸면 해당 그룹의 번호도 맞춥니다. 새로 추가한 미분류 문장도 화면에서 누락하지 않습니다. 작업별 설계 항목·활용 도구와 검토 기준은 항목 단위로 줄바꿈하고, 좁은 화면의 상세 요약은 목차로 표시합니다.

이미지나 파일을 추가하면 `assets/`에 파일을 넣고 `assets.js`의 해당 경로를 갱신합니다. 영상 파일은 실제 주소와 포스터가 있을 때 `type: 'video'`로 연결할 수 있습니다. 최신 개요 PDF 7·11쪽의 실제 YouTube 링크는 `projects.battle.videoUrl`과 `projects.jump.videoUrl`에서 관리하며 각 프로젝트의 ‘플레이 영상 보기’로 연결합니다. 자동 재생하지 않습니다.

실제 자료는 사용자가 제공한 포트폴리오 개요 21쪽, 일반 몬스터 범용 AI 17쪽, 가디언 기획 34쪽 전체에서 확인했습니다. 원본 PDF·PPTX는 수정하지 않습니다. 사이트에 타인의 프로젝트 설명·이미지·경력이나 임의의 성과 수치를 넣지 않았습니다. 전투 시간 3~5분·입장 조건·보상 등은 기획서의 목표와 제안 값입니다. [쪽별 대조 및 수정 기록](docs/source-review.md)을 참고하세요.

열람·다운로드 PDF 3종은 사용자가 제공한 PDF 원본으로 교체했습니다. 개요 21쪽, 일반 몬스터 AI 17쪽, 가디언 34쪽을 그대로 유지하며 파일 내용은 수정하지 않았습니다. 다운로드 시 제공받은 한국어 파일명으로 저장합니다. 각 문서 URL의 버전 값은 파일 해시를 기준으로 갱신해 이전 파일이 캐시에 남지 않도록 합니다. 표지와 주요 페이지 16개도 최신 PDF에서 다시 렌더링했습니다. 이미지에는 `sourceDocument`·`sourcePage`로 문서와 실제 쪽수를 기록합니다.

개요 PDF의 원본 열람·다운로드는 `#portfolio-overview`에 모았습니다. 헤더·첫 화면·연락처와 일반 작업 상세의 개요 링크는 이 영역으로 이동하며, 같은 파일을 바로 다운로드하지 않습니다. AI·가디언 기획서의 열람·다운로드는 각 카드와 상세에 유지합니다.

소개는 개요 2쪽의 사진·이름, 학력·프로젝트·전시 이력, 역량·도구 구성을 반영합니다. 사진은 원본 PPTX 내장 이미지를 사용하며 이력은 `content.js`의 `profile`에서 관리합니다. 프로젝트 기간은 자료 간 세부 월 표기가 달라 연도 단위로 표시합니다.

## 미리보기와 공개 반영

로컬 미리보기:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

실행 후 http://127.0.0.1:4173/ 에 접속합니다. 수정 후 브라우저를 새로고침합니다.

GitHub Pages는 `main` 브랜치의 `/ (root)`를 사용합니다. 변경된 HTML·CSS·JS뿐 아니라 `assets.js`와 실제 `assets/` 파일도 함께 커밋·푸시해야 합니다. `.nojekyll`을 유지합니다. 로컬에서 저장한 것만으로 공개 사이트에 반영되지는 않습니다.

`tmp/`와 `output/qa/`는 변환·검수용 임시 자료이며 공개 저장소에 포함하지 않습니다.

역량·도구 이름을 누르면 활용 범위와 관련 작업이 팝업으로 표시됩니다. 내용은 `content.js`의 `profile.skillDetails`에서 수정합니다. `items`는 할 수 있는 일, `workIds`는 관련 작업 ID 목록이며 사례가 없는 항목은 빈 배열로 둡니다. 카드와 상세의 목록 제목은 각 작업의 `metaLabel`에서 관리합니다. 게임 경험 카드의 ‘간단히 보기’를 누르면 짧은 팝업이 열립니다. 원문으로 확인한 플레이 기록과 기획에 참고할 관점을 나눠 표시합니다.

상세가 긴 두 기획서에는 ‘설계 항목 바로가기’를 제공합니다. 작업 자료로 바로 이동하는 링크와 이미지 확대도 지원합니다. 이미지 아래의 ‘클릭하여 확대’ 버튼은 바로 위 이미지를 누른 것과 동일하게 작동합니다. 확대 창에서 ‘원본 크기로 확대’를 누르면 작은 글자를 실제 이미지 크기로 읽을 수 있습니다. 좌우·상하 이동, 키보드 방향키, 화면 맞춤을 지원하며 닫기 버튼은 고정됩니다.
